# Client mods and game assets

Sanctuary's referee (GM) tools and a few housing features need small changes to the Free Realms
client UI, plus some data taken from the client. **Nothing from the game itself is stored in this
repository.** Everything below is either built from your own client install or copied from the
client's data, as described here.

## What lives outside this repository

| Asset | Where it comes from | Used for |
| --- | --- | --- |
| Free Realms client | The OSFR launcher (`%LOCALAPPDATA%/OSFRLauncher/Servers/<server>/Client`) | Playing, and the source of the stock UI movies the mods are built from |
| Asset server | `WebAPI:AssetUpstreamAddress` (default `http://osfr.editz.dev/assets`), or a local copy set in `WebAPI:AssetsDirectory` | The WebAPI proxies it to the client and adds the client mods to its manifest |
| Built client mods (`src/Resources/ClientMods/*.gfx`, `*.lst.z`) | Built locally with `build_client_mods.py` (git-ignored) | Referee Tools panel in the chat window and the UI below |
| `src/Resources/Names.json` | Generated by `extract_names.py` from the client's English locale | Item / NPC / house names in the referee panel's search |
| `src/Resources/ItemAbilities.json` | Generated by `extract_item_abilities.py` from the client's locale, `AbilityEffectTypeSettings.txt` and `ActorCompositeEffectDefinitions.xml` | What potions, scrolls, buff foods, orbs and loot bags do when used (heals, energy, coin/star boosts, stat buffs, speed, size, illusion forms, auras, fireworks, damage and holds on mobs, shared potions, reward table rolls); test with `!itemability` |
| `src/Resources/FirstTimeEvents.txt`, `GameTutorialData.txt` | Copied from the client's data tables | Ids for `!fte` and `!tutorial` |
| `src/Resources/Terrain/<zone>.terrain` (Fabled Realms, Lavender Coast) | `zone_server_terrain.py` from the zone's terrain chunks (`.gcnk`, version 5 or 6) | Standing NPCs on the ground; a zone with terrain but no `NavMeshes/<zone>.navmesh` gets one built from it at server start (and saved, so delete it to rebuild after the terrain changes) |

## Tools

- **Python 3** with **Pillow** (`pip install pillow`).
- **JPEXS Free Flash Decompiler** (`ffdec.jar`, https://github.com/jindrapetrik/jpexs-decompiler/releases).
- **Java** 8 or newer for ffdec (`--java`, defaults to the `java` on your PATH).

## Building the mods

The stock movies (`chatWindowCtrl.gfx`, `gamedock.gfx`, `dialog.gfx`, their `.lst` preload lists and the hub's tree
texture) are read straight from your client's `Assets_*.pack` files:

```
python build_client_mods.py --client "%LOCALAPPDATA%/OSFRLauncher/Servers/OSFR Public Server/Client" --ffdec path/to/ffdec.jar
```

With a local copy of the asset server (`<bucket>/<name>` folders), use `--assets <folder>` instead.
Both produce identical files.

The output goes to `src/Resources/ClientMods`. The WebAPI project copies that folder into its
output, serves the files, and patches them into the asset manifest it hands the client, so
**rebuild the WebAPI after building the mods**.

## Installing into a client

UI movies are loaded synchronously from the client's local packs, so they have to be installed
once per client (and again after each rebuild):

```
python install_client_mods.py --client "%LOCALAPPDATA%/OSFRLauncher/Servers/OSFR Public Server/Client"
```

This writes the built UI movies (the `.gfx` and `.lst` files) into a new `Assets_NNN.pack` (recorded in
`sanctuary_client_mods.txt`) and points `UI/UiModules/Main/wndChatLog.xml`, `wndGameDock.xml`, `wndDialogNew.xml`,
`wndAtlas.xml` and the rest at the renamed movies (the originals are kept as `*.sanctuary-backup`). In
`LoadingScreen.xml` it makes `sanctuaryLoadingScreen.swf` the only loading screen, commenting out the stock ones.
Close the client first.

Nothing else in the folder goes into the pack: published items and zones stream from the asset server, and a
copy in a read-only local pack would stop the client from taking a newer version (it hangs on "non-writeable pack
file").

It also enlarges the chat window to 2000x1045. The client clips every movie to its window, so this
is what lets the Referee Tools panel be dragged anywhere and resized (bottom-right grip, `[ ]` to
maximize). The client's Lua bottom-aligns the chat window, and the mod draws the chat movie 1:1
anchored bottom-left, so chat itself stays where it always was.

It also copies `lua/referee_tools.lua` to `Resources/Scripts/1` and `lua/client_extensions.lua` to
`Resources/Scripts/2` (see below).

Undo it with `--uninstall`.

## Referee client tools (Lua)

The retail client ships without its internal Lua: the `Admin` module, the `/dofile` binding and the
debug console switch. Its `startup.lua` still defines `dofileInternalOnlyCommand(name)`, which runs
`Client.PathScripts .. name` (`[Paths] PathScripts` in `ClientConfig.ini`, `./Resources/Scripts/` by default).

The server can call any client Lua function with three numbers (`AbilityPacketExecuteClientLua`,
Ability sub-op 17). When a referee finishes loading into the world it calls
`dofileInternalOnlyCommand(1)`, which runs `lua/referee_tools.lua` installed as `Resources/Scripts/1`. That
gives the referee:

- `/lua <code>` (`/lua =<expression>` prints the value)
- `/dofile <file>` (`/dofile 1` reloads the tools)
- `/admin on|off`, which sets the client's `Admin` global so its admin-only UI turns on, e.g. the atlas
  printing world coordinates on click
- `Client.EnableDebugConsole`

`!lua tools [referee]` reloads the tools. `!lua call <function> [x y z] [player]` calls any client Lua
function, e.g. `!lua call CuteMode:Big`. Both commands need the admin role.

The retail client also binds `/var <name>` and `/listvars`, which print `Client.*` variables.

## Client extensions (Lua)

The same way, every player gets `dofileInternalOnlyCommand(2)` the first time they finish loading into the world,
which runs `lua/client_extensions.lua` installed as `Resources/Scripts/2`: what Sanctuary adds to the client's own
scripts for everyone. A client without it logs the failed `dofile` to `Logs/LuaErrors.log` and carries on.

- Region badges: walking into a region plays its "Now entering" badge (`notifications.swf`'s `playZoneAnimation`),
  but the stock scripts only know area ids 2 to 10. `SanctuaryClient.RegionBadges` maps Sanctuary's own area ids
  (a zone's `AreaDefinitions` `Id`) to badges built by `REGION_BADGES`: 13 is Lavender Coast.

The client must be launched against a Sanctuary WebAPI that serves the same build
(`AssetDelivery:IndirectServerAddress=http://127.0.0.1:20040/assets`, which is the default in
`appsettings.json`). Otherwise the client sees a manifest mismatch and can't load the chat window.

## Regenerating item abilities

```
python extract_item_abilities.py --client "%LOCALAPPDATA%/OSFRLauncher/Servers/OSFR Public Server/Client"
```

Items only name an `ActivatableAbilityId`; what each one did lived on the original servers. The script picks a
behavior per ability from the item's description (tiers from the item names), maps buff tooltips to the
`CharacterStatId` the client reads, and checks every composite effect id against the client. Edit the
`ABILITIES` table and `DESCRIPTION_RULES` in the script rather than the JSON, then rerun it. Abilities that
`Consumables.json` already covers (food auras, transformations) are skipped.

Helpers for the table: `heal`/`energy`/`replenish` (potions), `stats`/`coins`/`stars`/`speed`/`scale`/`aura`
(timed buffs), `transform` (illusion forms), `cast` (fireworks), `frag`/`hold`/`blast`/`attack` (orbs and
grenades against mobs), `scare` (transform the user and make nearby mobs flee), `shared` (also applies to
other players within 15 m), `loot` (rolls a `Rewards.json` table) and `revive` (stands a knocked-out player
within 10 m back up where they lie). Models are checked against `Models.txt`.

## Server terrain and navmeshes

```
python zone_server_terrain.py --zone lavendercoast --chunks <folder with lavendercoast_*.gcnk>
```

Writes `src/Resources/Terrain/<zone>.terrain` from the ground of every chunk (not the tiles' objects). Delete
`src/Resources/NavMeshes/<zone>.navmesh` afterwards and the server builds a new one from it on its next start,
sized for a player (2 m tall, 0.6 m wide, 0.9 m steps, 45 degree slopes). Mobs, pets and the client's quest
breadcrumbs path on it; a zone without one gets straight lines.

## How the panel talks to the server

- Buttons send chat commands (`!gm`, `!npc`, `!prop`, `!house`, `!conv`, ...).
- The server answers with hidden system chat lines, `[[SANCTUARY_GM]]|kind|field|...`
  (`ChatHelper.SendGmPanelData`). The chat window mod swallows these and renders them.
- Free text in scripts, conversations and the player dialog is escaped as `\\` (backslash),
  `\n` (newline), `\p` (`|`), `\t` (tab) and `\s` for the spaces chat would otherwise trim or
  collapse (leading, trailing, or next to another space).
