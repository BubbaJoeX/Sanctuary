### Gameplay

What the server runs today, beyond logging in and walking around:

* **Combat** - Hostile NPCs fight back in the open world (`src/Resources/Mobs.json`), and the client's own combat mode shows them as enemies. Picking a fight switches a player to their combat job; job abilities, combat orbs, spheres and grenades hit, stun, root, sleep, knock back or scare mobs. A player a mob knocks out recovers at the zone's start after 8 seconds, unless an ally uses a Resurrection Scroll on them first: they get up where they lie with half their health, and mobs leave them be for 5 seconds.
* **Jobs and ranks** - Kills, quest rewards and finished collections earn stars for the active job, up to rank 20. Each rank needs 75 more stars than the last, adds 100 health and makes job abilities hit 5% harder, with the client's own level-up notice.
* **Loot** - Mobs roll a loot table (`src/Resources/Rewards.json`) for everyone who helped, at each mob type's drop chance. Loot bags such as the Thick Pocket Book open into coins, potions and scrolls.
* **Items** - 548 of the client's 686 usable items do something: potions, scrolls, buff foods, illusion foods, masks, fireworks, orbs and treats (`src/Resources/ItemAbilities.json`, generated by `ClientMods/extract_item_abilities.py`). Party crates, cakes, boomboxes and silly string come from `src/Resources/Consumables.json`.
* **Groups** - Invite to Group from a player's menu, or the client's group window, for groups of up to five: the first member leads, and group chat reaches every member. Members within 60 m of a kill share its stars, coins and loot roll.
* **Trading** - Trade from a player's menu: both sides offer items and coins, lock in, and accept, and the swap is saved in one go. Equipped and no-trade items stay put.
* **Hosted events** - Event staff (Mod and up) open an event at their spot with `!host open <event>`, which tells everyone online to type `!join`. Joining takes players there from anywhere, unless they're mid-fight or knocked out. `!host summon` gathers everyone who joined, `!host prize <event> <itemId> [qty]` and `!host coins <event> <amount>` reward them, `!host who` lists them, and `!host close` and `!host end` stop new joins and finish the event. `!event on/off <key>` still spawns or despawns the event's NPCs.
* **Scripting** - Zone and GM-authored Lua scripts can run events with all of the above. They can read a player's health, job, rank, coins and group, take items and coins, give stars, warp players between zones, hurt mobs or have NPCs attack players, and react to mob hits, kills and respawns, players entering or leaving a zone, events starting and ending, and players joining a hosted event. See `src/Scripts/README.md`.
* **Also** - Quests and the Hero's Journal, collections, housing, pets, mounts, guilds, friends, the coin store, the daily wheel and the Referee (GM) tools.

## Getting Started

This repository only contains the **server emulator** for Free Realms. To play the game, you must also have a **Free Realms client**. You can download the client using the **OSFR Launcher** available here: [OSFR Launcher](https://github.com/Open-Source-Free-Realms/Launcher).

### Prerequisites

Before you can use this software, ensure you have the following installed:

- **Visual Studio 2022**  
  Make sure to include the **.NET Framework development workload** during installation.

### Release

1. Clone the repo
   ```sh
   git clone https://github.com/Open-Source-Free-Realms/Sanctuary.git
   ```
2. Build the solution for `Sanctuary.Core` for `Release`
3. Create a file named `database.json` in the `Release` folder located within the new `bin` folder
4. Paste the following
   ```json
    {
    "Database": {
        "Provider": "Sqlite",
        "ConnectionString": "Data Source=D:\\Games\\Free Realms\\sanctuary.db;"
    }
   ```
5. Launch `Sanctuary.Login`, `Sanctuary.Gateway`
6. Connect to the client

**_IMPORTANT:_** Update the Data Source file path (D:\\Games\\Free Realms\\sanctuary.db) to match the location where your database files are stored.

**_NOTE:_** The following user should already exist, but if not then implement one with the following credentials:

```sh

```

### Debug

1. Clone the repo
   ```sh
   git clone https://github.com/Open-Source-Free-Realms/Sanctuary.git
   ```
2. Build the solution for `Sanctuary.Core` for `Debug`
3. Right-Click **'Manage User Secrets'** for the following projects:
   - `Sanctuary.Gateway`
   - `Sanctuary.Login`
   - `Sanctuary.Database`

4. Copy and paste the following configuration for **SQLite** into the secrets editor:

   ```json
   {
     "Database": {
       "Provider": "Sqlite",
       "ConnectionString": "Data Source=D:\\Games\\Free Realms\\sanctuary.db;"
     }
   }
5. Launch `Sanctuary.Login`, `Sanctuary.Gateway`
6. Connect to the client

**_IMPORTANT:_** Update the Data Source file path (D:\\Games\\Free Realms\\sanctuary.db) to match the location where your database files are stored.

## Roadmap

- [x] Open-world combat, job ranks and mob loot
- [x] Potions, scrolls, buff foods, orbs and other usable items, the Resurrection Scroll included
- [x] Groups and player-to-player trading
- [ ] Crafting (recipes): the client's RecipeStart has no server yet, and the recipe data is missing
- [ ] Job minigames (Chef, Miner, Blacksmith...): the server only runs the daily wheel
- [ ] Fishing, matchmaking queues and housing ratings
- [ ] Combat pet summons (Bravery Biscuit, Creepy Construct Caller)

See the [open issues](https://github.com/Open-Source-Free-Realms/Sanctuary/issues) for a full list of proposed features (and known issues).
